# Figure Alert 진행 현황

기준일: 2026년 10월 21일
개인 프로젝트 · 2026년 9월 초부터 개발 중
담당: 서비스 기획, 도메인·DB 설계, 백엔드 API 개발

## 2026-10-21 구독 PUT 구현·검증

구독 Controller·응답 DTO·입력 검증·전용 오류 코드를 연결했습니다. 신규 201·기존 갱신 200·설정 누락 400/Service 미호출을 standalone MockMvc로 검사했습니다. Entity의 전체 끄기·예약 시작만 켜기, Service의 생성·갱신·없는 회원/캐릭터 거부도 테스트했습니다. 전체 test 실행 결과 10개 통과(실패 0, 오류 0)입니다.

권한 보완·실제 DB 저장/동시성·조회/취소·복수 누락 상세·JSON 자료형 엄격 검사는 아직 남아 있습니다. 아래 2026-10-20 점검 내용 중 ‘구독 Controller 없음’ 등은 당시 기록이며 현재 상태는 이 항목과 [오늘 기록](scrum/2026-10-21.md)을 우선합니다.

## 2026-10-20 MVP 재점검

현재 Controller·Service·Repository·보안·DTO·테스트를 재점검했습니다. 자세한 현황과 권장 순서는 [MVP 완성 작업 목록](MVP_BACKLOG.md), 실행 결과와 활동은 [오늘 기록](scrum/2026-10-20.md)에 정리합니다. 아래의 과거 ‘이번 정리에서 실행하지 않음’은 기존 점검 기록이며 최신 실행 여부는 오늘 기록을 기준으로 합니다.

우선순위 제안: **빌드·테스트 기반과 필수 권한 보완 → 구독 PUT/조회/취소 및 동시성 검증 → 공식 이벤트·내부 알림 → 배포 필수 보완과 클라이언트 연결 → 이용 관찰·포트폴리오**. 캐릭터 등록의 ADMIN 제한 누락과 공개 조회 규칙 불일치를 코드에서 발견했습니다. 실제 Security 응답은 아직 미검증입니다. 기능 코드 변경 없이 현황·우선순위 문서를 보완했습니다.

실행 결과: Java 21로 전체 소스·테스트 컴파일과 기존 제조사 중복 단위 테스트 1개가 통과했습니다. 구독·권한·DB 통합 검증은 여전히 남아 있습니다. 보고서: [테스트 결과](../build/reports/tests/test/index.html).

## 현재 어디까지 진행했나요?

피규어 카탈로그와 회원·인증의 기초 코드를 작성했고, 현재 관심 캐릭터 구독 기능을 구현하고 있습니다. 구독 요청 DTO와 엔티티, 생성·설정 갱신 서비스 로직까지 작성한 상태이며, 다음 작업은 구독 API 연결과 검증입니다.

이 문서는 현재 소스 코드와 작업 기록을 대조해 정리했습니다. 코드 작성 여부와 실제 동작 검증을 구분하며, 빌드·테스트·DB 연동은 이번 정리 과정에서 실행하지 않았습니다.

## 프로젝트가 해결하려는 문제

판매가 종료된 피규어 정보를 다시 찾기 어렵고, 관심 캐릭터의 신제품·재발매 소식을 여러 곳에서 확인해야 하는 불편을 줄이고자 합니다. 과거부터 발매 예정 피규어까지 조회하고, 관심 캐릭터의 소식을 구독하는 서비스를 목표로 합니다.

## 기능별 진행 현황

### 카탈로그 — 코드 작성 · 검증 대기
- 피규어·캐릭터·제조사·발매 정보 도메인과 JPA 연관관계 작성
- 피규어 등록·조회·수정·삭제 API 작성
- 피규어 이름·캐릭터 이름 검색 및 제조사 필터 작성
- 캐릭터 등록·조회·검색 및 캐릭터별 피규어 조회 API 작성
- 제조사 등록·조회·수정·삭제 및 발매 정보 등록·조회·일정 변경 코드 작성
- 요청·응답 DTO와 공통 예외 처리 작성
- 남은 확인: 실제 DB 연동, 관계 변경·삭제 시 데이터 정합성, 정상·실패 응답 검증

### 회원·인증·권한 — 코드 작성 · 검증 대기
- 회원가입·로그인 로직, 비밀번호 해시 저장과 검증 작성
- JWT 발급·인증 필터와 Spring Security 접근 규칙 작성
- 조회 공개 및 일부 관리 API의 ADMIN 권한 규칙 작성
- 남은 확인: 비로그인·USER·ADMIN별 접근, 잘못된 토큰·만료 토큰, 전체 API의 권한 규칙 대조
- 토큰 자동 갱신은 미구현

### 캐릭터 구독 — 구현 중 · 현재 작업
- 회원·캐릭터 조합의 중복 방지를 위한 UNIQUE 제약 매핑 작성
- 요청 DTO에 Boolean 다섯 필드와 @NotNull 작성
- 엔티티에 알림 설정 다섯 필드와 NOT NULL 매핑 작성
- 신규 구독 생성 및 기존 구독 설정 전체 갱신 서비스 로직 작성
- 생성·갱신 여부를 구분하는 반환값 작성
- 아직 구독 Controller가 없어 외부 요청에서 서비스까지 연결되지 않은 상태
- PUT API 연결, 본인 식별·권한, 입력 오류 처리, 동시 요청 검증 필요
- 현재 Security 설정의 구독 POST·DELETE 규칙을 PUT 설계와 맞출 필요 있음

알림 설정 대상은 신규 발표, 예약 시작, 예약 마감, 재발매, 프라이즈 등장 예정의 다섯 종류입니다. 설정 저장 로직과 실제 알림 생성·전달은 별개이며, 알림 기능은 아직 구현 전입니다.

### 내부 알림 — 예정
- 공식 이벤트에 따른 내부 알림 생성·조회·읽음 처리
- 예약 일정 처리와 일정 변경 반영
- 반복 실행·중복 조건에서도 동일 알림이 중복 생성되지 않는지 검증
- 앱 미접속 중 전달을 위한 푸시는 후속 검토

### 배포·사용자 검증 — 예정
- 초기 배포 환경과 클라이언트 제공 방식 결정
- 핵심 사용자 흐름을 연결한 뒤 오류·사용자 피드백 관찰
- 실제 출시일 미정, 사용자 수·매출·성능 개선의 실측 성과 없음

## 지금까지의 주요 설계 결정

### 피규어·캐릭터 관계를 별도 엔티티로 표현
하나의 피규어에 여러 캐릭터가 포함되고, 하나의 캐릭터가 여러 피규어에 등장하는 관계를 FigureCharacter로 표현했습니다. 단순 필드보다 관계 관리 코드가 늘어나지만, 양쪽 기준으로 조회하고 관계를 관리할 수 있습니다. 관계 수정·삭제 시 정합성을 검증할 예정입니다.

### 검색 결과의 캐릭터 정보를 일괄 조회
검색된 피규어 ID 목록을 기준으로 연관 캐릭터 정보를 조회한 뒤 피규어별로 묶어 응답에 포함하도록 작성했습니다. 조회·조립 코드가 추가되는 대신, 해당 검색 경로에서 피규어마다 별도 조회하는 구조를 줄이고자 했습니다. 실제 쿼리 수와 성능 효과는 미측정입니다.

### 구독 설정은 PUT으로 전체 교체하는 방향
설정 다섯 값을 모두 받고 기존 구독이 있으면 전체 설정을 교체하는 방식으로 결정했습니다. 누락을 false로 오해하지 않도록 요청은 Boolean과 @NotNull로 표현하고, 엔티티는 boolean과 NOT NULL 매핑을 사용했습니다. 필수 값을 모두 보내야 하는 부담을 받아들이는 대신 요청 의미를 명확히 했습니다. Controller 연결과 실제 요청 검증은 남아 있습니다.

### 오류는 식별 코드와 상세 정보를 제공하는 방향
누락·null은 요청 전체를 거부하고, 여러 누락 필드를 개발자용 상세 정보로 제공하기로 결정했습니다. 오류 코드는 INVALID_SUBSCRIPTION_SETTINGS를 사용하기로 했습니다. 현재 공통 오류 응답은 status·message만 제공하고 검증 오류도 첫 항목만 반환하므로, 이 결정은 아직 반영 전입니다.

## 다음 작업과 완료 기준

1. 구독 PUT API와 인증 사용자 연결
- 요청의 회원 번호를 신뢰하지 않고 인증 사용자 기준으로 처리
- 신규 생성과 기존 설정 갱신을 구분해 응답
- 구독 API와 Security 접근 규칙을 함께 확인

2. 요청 검증과 오류 응답 연결
- 다섯 값의 true·false 허용, 누락·null 거부
- 잘못된 자료형의 자동 변환 여부를 확인하고 결정한 거부 정책 적용
- 잘못된 요청은 Service 호출·부분 저장 없이 거부

3. 구독 저장 동작 검증
- 새 구독 생성, 기존 설정 전체 교체, 모두 끔, 동일 요청 반복 검증
- 각 설정을 하나씩 켜서 동일 타입 인자의 순서 혼동 확인
- 없는 회원·캐릭터 및 같은 조합의 동시 요청 검증
- UNIQUE 매핑뿐 아니라 실제 DB 제약 적용과 경쟁 요청 결과 확인

4. 내부 알림 구현 후 초기 배포
- 알림 생성·조회·읽음, 중복 방지, 일정 변경 검증
- 핵심 사용자 흐름을 연결해 배포하고 피드백 수집

## 검증 현황과 남은 한계

제조사 중복 이름 등록 시 예외가 발생하고 저장하지 않는지 확인하는 단위 테스트 코드가 있습니다. 이번 문서 정리에서는 실행하지 않았으므로 통과했다고 표시하지 않습니다.

현재 기능별 API·DB 통합 검증, 구독 테스트, 권한 테스트, 동시성 테스트가 남아 있습니다. 검색 성능 개선이나 운영 성과도 아직 측정하지 않았습니다.

첫 배포는 카탈로그 조회·회원/인증·캐릭터 구독·내부 알림 V1에 집중합니다. 핵심 흐름을 먼저 검증하기 위해 위시리스트·리뷰·개별 피규어 구독은 후속 범위로 두었습니다.
