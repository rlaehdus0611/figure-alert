# 트러블슈팅 기록

실제로 관측·재현한 문제만 해결 사례로 기록한다. 예상 위험과 해결 완료를 구분한다. 현재 이 문서에 해결 완료 사례는 없다.

## 기록 양식

- 제목 / 일자 / 관련 이슈·PR:
- 사용자가 겪은 문제와 영향:
- 환경·버전·재현 조건:
- 기대 행동 / 실제 행동:
- 로그·실패 테스트 등 증거(개인정보·비밀값 제거):
- 원인 가설 / 확인·기각 근거:
- A안 / B안 비교와 선택 이유:
- 수정 파일·핵심 변경:
- 재현 테스트의 수정 전 실패 / 수정 후 결과:
- 부작용·회귀 검증:
- 측정 결과(기간·표본·단위):
- 남은 한계 / 재발 방지:
- 내가 설명할 핵심 원리:

## 재현할 위험 목록 — 아직 해결 사례 아님

| 위험 | 검증 계획 | 사용자 관점의 완료 기준 |
|---|---|---|
| 같은 캐릭터 동시 구독 | 독립 트랜잭션으로 동일 회원·캐릭터 경쟁 요청 | 행 1개, 정의한 응답·설정 정책 충족 |
| 반복 PUT | 같은 전체 설정 요청 반복 | 설정·구독 상태 일치 |
| 캐릭터·피규어 중복 구독 | 같은 이벤트가 두 구독 조건 만족 | 회원별 이벤트 알림 1개 |
| 스케줄러 재실행 | 같은 대상·이벤트를 반복 처리 | 추가 중복 알림 없음 |
| 예약 일정 변경 | 처리 전후 날짜 변경·정책별 재실행 | 이전 일정으로 잘못 알리지 않음 |
| 과거 상품 등록 | 아카이브 추가와 발표 이벤트 분리 | 과거 상품 신규 발표 알림 없음 |
| 다른 회원 구독 변경 | 인증 사용자와 요청 대상 불일치 | 타인 설정 변경 불가 |

각 검증은 기능 구현 시 수행하고 결과를 채운다. 초기에는 로컬 트랜잭션과 DB 제약을 검증하며, 외부 발송·분산 처리는 도입 시 별도 사례로 기록한다.
