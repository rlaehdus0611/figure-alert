# 일일 스크럼과 작업 기록

개인 프로젝트의 진행·결정·검증 근거를 남긴다. 실제 팀 스크럼이나 사람과의 협업 경험으로 표현하지 않는다. 본인이 최종 판단과 설명을 맡고 AI는 조사·초안·검증 보조로 사용한다.

## 운영 방식

- 작업 시작: 전 작업일 결과, 오늘 목표, 막힌 점을 짧게 기록한다. 목표는 오늘 확인할 수 있는 크기로 잡는다.
- 작업 종료: 실제 변경·검증·배운 점·다음 행동을 추가하고 ../PROGRESS.md 상태를 갱신한다.
- 기록 일자는 한국 시간 YYYY-MM-DD다. 과거 활동은 당시 근거 없이 소급 작성하지 않는다.
- 이 채팅에서 개발 작업을 진행할 때 해당 날짜 파일을 갱신한다. 작업하지 않은 날의 가짜 기록·예약 자동 실행은 만들지 않는다.
- 실제 작업시간·인터뷰·리뷰·사용자 수·매출·테스트 결과를 추정해 채우지 않는다. 실패나 계획 변경도 그대로 남긴다.
- 같은 문서의 반복 서술은 줄이고 설계·이슈·PR·테스트 증거로 연결한다. 토큰·비밀번호·개인정보는 기록하지 않는다.
- 매주 작업한 기록을 기준으로 완료 결과·미해결·다음 우선순위를 요약한다. 주간 기록도 관측된 작업이 있을 때 작성한다.

## 일일 양식

파일명: YYYY-MM-DD.md

```markdown
# YYYY-MM-DD 일일 스크럼·작업 결과

## 시작 점검
- 전 작업일 결과와 근거:
- 오늘 목표 / 완료 기준:
- 막힌 점·확인할 가정:

## 실제 작업과 결정
- 해결할 문제:
- 비교한 대안:
- 선택 이유와 감수한 단점:
- 변경 파일·이슈·PR:
- 본인이 판단·설명할 부분 / AI 지원 범위:

## 검증과 결과
- 실행 환경·방법:
- 실제 결과와 근거:
- 미실행·미확인·남은 한계:
- 실제 투입시간·비용(확인된 경우):

## 회고와 다음 작업
- 배운 점·설명하지 못한 부분:
- 다음 작은 작업:
```

작은 문서 작업은 불필요한 항목을 생략할 수 있다. 기능 구현은 정상·실패·경계·필요한 동시성 기준을 포함한다. 테스트 통과와 사용자 가치 검증은 별도로 쓴다.
